# VoiceAssist — техническое задание

Статус: согласованная основа для проектирования и приёмки; функции ещё не реализованы. Язык интерфейса — русский. Дата редакции: 13 октября 2026 года.

## 1. Цель и границы

VoiceAssist — бесплатный локальный голосовой помощник для практически незрячего пользователя ПК. Он должен позволять без мыши выполнять основные действия Windows, работать с Google Chrome, читать доступный текст страниц, управлять поддерживаемым видео и безопасно переносить файлы между USB-накопителями. Интернет нужен для сайтов, но системные, файловые и голосовые функции должны работать без него. Платные API, подписки, облачные модели и отправка аудио на серверы не допускаются.

Поддерживаемые ОС: **только 64-разрядные Windows 7, 10 и 11**. Целевая маломощная конфигурация: Intel Core i5 третьего поколения, 6 ГБ DDR3, старый HDD (уточнено пользователем 13.10.2026; раньше было «четвёртого поколения»); проверить также SATA SSD. Браузер — установленный **Google Chrome той версии, которая реально запускается на данном ПК**. Версия определяется при установке и диагностике; доступность каждой браузерной функции проверяется отдельно. Windows 7 и обычные выпуски Windows 10 уже вышли из поддержки Microsoft; Chrome 109 — последняя ветка для Windows 7. Поэтому работа конкретных сайтов, расширений и плееров на Windows 7 не гарантируется и требует отдельного испытания. [Microsoft: Windows 7](https://learn.microsoft.com/en-us/lifecycle/products/windows-7), [Microsoft: Windows 10](https://learn.microsoft.com/en-us/lifecycle/announcements/windows-10-end-of-support), [Google: требования Chrome](https://support.google.com/chrome/a/answer/7100626?hl=en-EN).

Критерий продукта — самостоятельное выполнение сценариев незрячим пользователем с понятным голосовым итогом. «Максимум команд» не должен ухудшать надёжность и сохранность данных.

## 2. Голосовой интерфейс и состояние

- После входа пользователя в Windows помощник запускается автоматически, если эта возможность включена при установке. После подготовки микрофона, распознавания, маршрутизации команд и синтеза речи он произносит «Помощник готов. Скажите: помощник, какие команды доступны». Это сообщение означает готовность **самого приложения принимать команды**, а не окончание загрузки всей Windows. При долгом запуске — отдельный короткий сигнал ожидания; при недоступном микрофоне — отличимый сигнал ошибки и доступная диагностика с клавиатуры.
- После распознавания каждой команды сразу говорить: **«Ожидайте, идёт выполнение команды»**. Затем озвучивать итог с названием команды: **«Команда „…“ выполнена»** только после проверки успеха. Для долгой операции можно дополнительно назвать прогресс. Если результат не подтверждён, сказать «команда передана, но результат не подтверждён»; при ошибке — «команда не выполнена» с причиной. Нераспознанную или неоднозначную опасную команду не выполнять. Команда «Замолчи» прерывает речь без нового длинного ответа.
- Короткие ответы для частых действий; «Повтори», «Замолчи» и «Отмена» действуют в любом контексте. Длинную озвучку можно прервать голосом. После сна или переподключения микрофона восстановить приём и сообщить о восстановлении.
- Предусмотреть активацию ключевой фразой «Помощник» и режим ограниченного непрерывного набора команд. Режим по умолчанию выбрать по измеренным ложным срабатываниям, задержке и нагрузке. Звук фильма или телевизора не должен бесконтрольно запускать действия; опасные команды требуют отдельного подтверждения.
- Русские варианты формулировок обрабатывать локально: нормализация, словари, шаблоны, ограниченное нечёткое сопоставление. При нескольких возможных целях — короткий уточняющий вопрос. Не обещать понимание любой свободной речи.

## 3. Контекстная справка и каталог команд

«Какие команды мне сейчас доступны?», «Что я могу сделать?», «Помоги» доступны всегда. Сначала назвать **3–5 реализованных действий текущего контекста**, затем кратко напомнить общие команды. «Дальше» читает следующую группу, «Повтори» повторяет её, «Все категории» называет разделы. Предлагать действие лишь когда нужные устройство, окно, сеть, расширение или плеер доступны; ограничение озвучивать. Каталог ниже задаёт намерения и проверяемое покрытие, а не обещание произвольных фраз.

«Который час?» читает **локальные системные часы Windows** и при необходимости уточняет «по часам компьютера»; точность синхронизации с интернетом не обещается. «Громче» уточняет цель, когда возможны громкость системы, помощника и плеера; предпочтение можно сохранить в настройках. Глобальные команды доступны в любом контексте, команды страницы относятся к активной вкладке, окон — к активному окну. Списки элементов имеют устойчивые номера в рамках текущей версии страницы; после изменения страницы список сбрасывается с уведомлением.

Для каждого намерения реестр хранит контекст, варианты фраз, необходимые компоненты, действие, проверку результата, тексты успеха и ошибки, правило подтверждения. Новые формулировки добавляются после испытаний с пользователем.

### Повседневные локальные функции

- Таймеры и будильники: установка, запрос оставшегося времени, отмена, звуковой и голосовой сигнал по срабатыванию. Таймеры используют монотонные часы, чтобы изменение системного времени не сдвигало их; после перезапуска незавершённый таймер не обещается без отдельной реализации восстановления. Будильник и напоминание с календарным сроком сохраняются локально и после перезапуска восстанавливаются с явным сообщением о пропущенном событии.
- Напоминания и заметки: голосовое добавление, чтение короткими группами, удаление только с подтверждением конкретной записи. Хранить локально; не передавать содержание на сервер. При неоднозначном распознавании текста переспросить до сохранения.
- Вычисления и конвертации: ограниченный проверенный набор арифметических операций и единиц (например, длина, масса, время). Не вычислять произвольный код и не угадывать единицы при неоднозначности.
- Время и дата — по системным часам, с уточнением источника; поиск программ и файлов — через локальные индексы/ограниченные каталоги без постоянного сканирования HDD.
- Погода, новости и веб-поиск — только при работающ интернете и выбранном надёжном бесплатном источнике; произнести источник и время данных. Офлайн честно сообщать о недоступности. Никакой общей «Siri-совместимости» не заявлять.

## 4. Chrome, сайты, чтение страниц и видео

- Открывать и закрывать Chrome, управлять вкладками, историей, загрузками, закладками, навигацией и поиском. Свободный текст после «найди» передавать в поисковый запрос. Переключаться на уже открытую вкладку сайта, если её можно надёжно определить.
- Любимые сайты и синонимы хранить в редактируемой конфигурации. **HDRezka** — сохранённый пользователем адрес, а не зашитый домен. Filmix/FilmFix и другие названия добавлять после уточнения адреса при настройке. «Сайт открыт» говорить после подтверждения загрузки нужной страницы; при тайм-ауте сообщать неопределённый результат.
- Читать доступные заголовки, основной текст, ссылки, кнопки, поля, доступные имена и ARIA-атрибуты. На испытанных сайтах выделять карточки фильмов и названия видео; читать по пять элементов, открывать выбранный номер, давать описание и возвращаться к списку. Не обещать распознавание текста внутри изображения, универсальное понимание сайтов или обход недоступной разметки.
- Для поддерживаемого HTML5-плеера использовать его доступные средства управления и проверять изменение состояния после команды. Для нестандартного плеера нужен отдельный проверенный адаптер. «Следующая серия» и качество доступны лишь при обнаруженном управлении. При ограничении озвучивать, что конкретное действие на этом плеере не поддерживается.
- Архитектурный кандидат — расширение Chrome Manifest V3 с минимальными разрешениями и Native Messaging для связи с локальным процессом; фактическую совместимость API и способ установки проверять на Chrome каждой целевой ОС. Chrome указывает доступность `chrome.scripting` с Chrome 88 и MV3, а Native Messaging требует регистрации локального host и разрешённого origin. [Chrome: scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting), [Chrome: Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging).
- Блокировщик рекламы не является частью VoiceAssist. Можно предложить совместимое бесплатное расширение после проверки версии Chrome и разрешения владельца; не устанавливать его молча. Не обходить CAPTCHA, платный доступ и ограничения сервиса.

## 5. Windows, доступность и ошибки

Использовать Windows UI Automation и системные API там, где элементы доступны: читать название активного окна, доступные кнопки и списки, перемещаться между элементами, активировать выбранный элемент, сообщать об ошибках и доступных системных уведомлениях. Совместимость с NVDA проверять отдельно; сообщения двух синтезаторов не должны накладываться. VoiceAssist не обязан полностью заменять NVDA. Закрытие окна не должно заявляться успешным, если оно осталось открытым из-за запроса сохранения. Перед выключением и перезагрузкой повторить конкретное действие и запросить подтверждение; если виден запрос о несохранённых данных, озвучить его.

Обрабатывать отсутствие микрофона, синтезатора, сети и Chrome; отключённое расширение; ошибку загрузки, отсутствие элемента, отказ доступа, отключение USB, недостаток места и ошибки чтения/записи. Сбой одного модуля не должен молча завершать всё приложение. Если голос недоступен, предусмотреть отличимые сигналы и доступный журнал/диагностику для помощника пользователя.

## 6. Файлы и USB

- При запуске сохранить снимок уже доступных томов; в дальнейшем событие подключения или редкая проверка выявляет новые тома относительно снимка. Рекомендовать пользователю подключать флешки после готовности помощника, но уже подключённые USB-устройства тоже определять по USB-шине. Новый том — лишь кандидат, а не доказательство, что это флешка. Не сканировать диски постоянно.
- Определять подключение и отключение съёмных накопителей, их метки, ёмкость и свободное место; тип устройства называть лишь при достоверном определении. Различать «первую» и «вторую» флешки устойчивым идентификатором в текущей сессии, а не только буквой диска. При изменении подключений повторно уточнять соответствие номеров устройствам.
- До копирования определить источник и назначение, посчитать файлы и объём, проверить место и конфликты имён, исключить копирование в самого себя, озвучить конкретный план и получить подтверждение. По умолчанию копировать в отдельную папку назначения без удаления исходников и без перезаписи. При конфликте — спросить, как поступить.
- Сообщать начало, прогресс по запросу или значимым этапам и проверенный итог: сколько файлов скопировано, пропущено, не удалось проверить. Проверять ошибки записи и итоговые размеры/наличие; контрольные суммы применять для критичных файлов или по настройке. При отключении устройства остановиться и сохранить сведения для безопасного продолжения. Отмена не должна удалять уже успешно скопированные файлы без отдельного решения пользователя.
- Учитывать ограничение FAT32 для файла более 4 ГБ и сообщать о нём до операции. Перемещение, удаление, перезапись и безопасное извлечение требуют отдельной логики; удаление по умолчанию — в корзину, с подтверждением конкретного объекта и действия. Не форматировать накопители.

Команды «флешка», «флеш-накопитель» и «внешний диск» относятся к USB/внешним накопителям. Фраза «запиши на диск …» относится к **оптическому CD/DVD через привод** и не запускает USB-копирование. Нужно определить точный источник («…»), целевой привод/носитель, свободное место и конфликты, озвучить план, получить конкретное подтверждение, сообщать прогресс и проверить итог. При неоднозначности уточнить. Перед записью проверить, что привод умеет записывать, а вставленный носитель совместим и пуст либо допускает перезапись; при отсутствии записывающего привода честно отказать. Кандидат для Windows 7/10/11 — системный IMAPI 2, поддерживающий перечисление приводов, проверку носителя, запись и события прогресса; фактическую реализацию и проверку на оборудовании выполнить отдельно. [Microsoft: запись через IMAPI](https://learn.microsoft.com/en-us/windows/win32/imapi/burning-a-disc), [Microsoft: IDiscFormat2Data](https://learn.microsoft.com/en-us/windows/win32/api/imapi2/nn-imapi2-idiscformat2data).

## 7. Архитектура, ограничения и поставка

Предварительный стек: Python; Vosk с небольшой локальной русской моделью; RHVoice либо другой бесплатный локальный синтез; Windows UI Automation/WinAPI; расширение Chrome и Native Messaging; JSON или SQLite для настроек; бесплатный сборщик EXE и установщик. Выбор каждой зависимости закрепить после проверки лицензии, наличия сборки и работы на **всех трёх** ОС, особенно Windows 7. Допустима замена на более лёгкий совместимый компонент с обоснованием. Компоненты разделить на речь, маршрутизацию намерений и диалог, Windows/UI Automation, браузер/расширение, USB/файлы, подтверждения и настройки. Сетевой контент считать недоверенным: текст страницы и звук видео не превращать в команды; Native Messaging должен проверять отправителя, формат и список допустимых операций. Не запускать основное приложение с правами администратора без необходимости; не хранить пароли и не исполнять произвольные CMD/PowerShell-команды из речи.

Для целевого ноутбука: целевое ожидание до 150–200 МБ RAM и в среднем до 3–5% одного логического процессора; отклик распознавания желательно менее секунды после конца фразы. Это **измеряемые цели, не гарантии**. Не использовать Electron, тяжёлые локальные модели, постоянное сканирование дисков, второй браузер и тяжёлый GUI. USB отслеживать по событиям; тяжёлую работу вынести из основного потока; ограничивать очереди и логи. Измерить работу вместе с Chrome и видео на HDD и при возможности SSD.

Установщик проверяет ОС и разрядность, компоненты речи, микрофон и Chrome; развёртывает модель, синтез, локальный host и настройку автозапуска, предлагает разрешённый способ установки расширения, выполняет голосовую проверку и предоставляет удаление. Нужен отдельный простой режим настройки для родственника: микрофон, голос/скорость, сайты и синонимы, автозапуск, проверка расширения, журнал ошибок; он не работает постоянно в фоне. Поставка: EXE, установщик, исходный код, инструкции по установке, настройке и голосовым командам, список реально поддержанных сочетаний ОС/Chrome/сайтов/плееров и результаты тестов. При разработке вне Windows результаты испытаний на Windows не выдумывать.

## 8. План реализации

1. **Проверка совместимости и основа.** Зафиксировать поддерживаемые версии зависимостей для Windows 7/10/11 x64 и Chrome; реализовать локальную речь, маршрутизатор, автозапуск, состояние готовности, итоговые ответы и глобальную справку. Выход этапа: голосовой сценарий после входа в систему и работа основных системных команд без сети.
   Затем добавить локальные часы, таймеры, напоминания, заметки и ограниченные вычисления; проверять их отдельно от сетевых сценариев.
2. **Браузер.** Реализовать расширение/связь, вкладки, поиск, чтение страницы, сохранённые сайты, нумерованные списки, затем проверить конкретный каталог фильмов и HTML5-плеер. Выход: воспроизводимый сценарий поиска и просмотра на явно указанной испытанной конфигурации.
3. **Файлы и USB.** Реализовать обнаружение устройств, обзор файлов, копирование с планом, подтверждением, отменой, проверкой и восстановлением после ошибок. Выход: безопасный сценарий двух флешек.
4. **Доступность и настройка.** Чтение Windows через UI Automation, проверка работы с NVDA, режим настройки помощника, уточнение диалогов по пользовательским испытаниям.
5. **Оптимизация и выпуск.** Измерения на целевом оборудовании, исправления, тесты по матрице ОС/Chrome, установщик и документация. Каждый этап закрывать только после демонстрации его сценариев и фиксации ограничений.

## 9. Проверяемые критерии приёмки

| Проверка | Условие принятия |
|---|---|
| Матрица ОС | Установка, запуск, автозапуск и базовые офлайн-команды проверены отдельно на Windows 7, 10, 11 x64; неподдерживаемая разрядность отклоняется понятно. Для каждого испытания записаны версия ОС и Chrome. |
| Готовность | После входа в Windows сообщение «готов» звучит только когда микрофон, распознавание, команды и синтез принимают тестовую фразу; отсутствие микрофона даёт различимый сигнал и диагностику. |
| Голосовой итог | Для каждой тестовой команды есть подтверждённый результат, честное «не удалось проверить» либо ошибка. Начальный ответ о долгой операции не засчитывается как её успешный итог. |
| Два сигнала команды | В пробах голосового режима «Ожидайте, идёт выполнение команды» звучит до действия, а итог с названием команды — после него. «Выполнена» не звучит при ошибке или непроверенном результате; «Замолчи» прекращает озвучку. |
| Справка | В каждом проверяемом контексте на вопрос звучат 3–5 применимых действий и общие команды; «Дальше», «Повтори», «Замолчи» работают. Недоступная функция не предлагается как доступная. |
| Системные сведения | Время и дата совпадают с локальными системными часами Windows; проверяются также офлайн. |
| Повседневные функции | Таймер срабатывает по монотонному времени, даже если системные часы изменились; напоминание и заметка сохраняются локально и читаются после перезапуска; арифметика не исполняет произвольный код. Погода и новости без проверенного источника честно недоступны. |
| Chrome и сайт | Chrome открывается и закрывается с проверкой состояния; сохранённый адрес HDRezka открывается либо озвучивается точная причина неуспеха. Сайт не считается поддержанным только из-за открытия URL. |
| Страница и видео | На заранее зафиксированных испытательных страницах озвучиваются реальные заголовки/элементы, выбирается номер из текущего списка; на поддерживаемом плеере проверяется изменение состояния play/pause и перемотки. Для неподдерживаемого плеера — честное сообщение. |
| Файлы и USB | Два устройства различаются после смены букв; копирование требует озвученного плана и конкретного подтверждения. Сверяются число/размеры файлов, фиксируются пропуски. Проверяются конфликт имён, нехватка места, файл >4 ГБ на FAT32, отключение устройства, отмена и возобновление. Источник остаётся неизменным. |
| Безопасность | Текст страницы и звук видео не запускают команды; выключение, удаление, перезапись и перемещение требуют конкретного подтверждения; произвольная shell-команда из речи не выполняется. |
| Устойчивость и ресурсы | Проверяются ≥100 вариантов формулировок, разные темпы речи, шум, работа без сети, с NVDA и непрерывная сессия 8 часов. RAM/CPU и задержки измеряются на целевом или сопоставимом ПК; при превышении целей фиксируются фактические значения и причина. |
| Поставка | Установщик и удаление работают; документация позволяет помощнику настроить микрофон, Chrome, сайты и автозапуск; перечень поддержанных сайтов и плееров соответствует проведённым испытаниям. |

Автоматические тесты покрывают парсер, диалоги, подтверждения, расчёт копирования и ошибки; ручные испытания проверяют реальную речь, UI, сайты, USB и доступность с незрячим пользователем. Не объявлять критерий выполненным по имитации или заглушке.
